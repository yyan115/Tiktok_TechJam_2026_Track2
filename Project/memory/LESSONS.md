# LESSONS — rules learned; check before working, add the moment one is learned

1. **Organizer-tested dead ends — never retry these** (published in their starter-kit README with numbers): adding more feature fields (CWM's 13 fields: 0.5940 vs 0.5950, noise); bigger embeddings (k=8/16/32: 0.5895/0.5902/0.5887, flat). Capacity and static features are NOT the bottleneck.
2. **Pure user-side features are mathematically worthless here.** Ranking happens within each user, so any per-user-constant term cancels (organizers verified: identical scores to the digit). User signals only help through crosses with item-side features or through sequences.
3. **The doc's "Limits" row is wrong** (says NDCG@10 / Recall@50 / click-positive). The shipped scoring code is authoritative: GAUC + nDCG@5, label = long_view, primary = their mean. Recall isn't scored (≈0.999 for any model — each user has ~5 impressions).
4. **Judge progress against 0.8645, not 1.0.** 27.1% of test users are all-negative (nDCG 0 forever), 9.2% all-positive. Baseline 0.5946 already holds ~31% of the attainable range; headroom ≈ 0.27 (0.247 on validation, ceiling 0.8484).
5. **FM seed noise is 0.0008** → convergence rule ε=0.002 over N=3 iterations. Don't celebrate sub-noise "wins".
6. **Submission format is strict:** row_id must be 0-based, gapless, aligned with data.load() order; (user_id, video_id) is NOT unique (3.06% duplicate pairs). Always run `submit.py --check` before designating anything final.
7. **Baselines reproduced on this machine 28 Aug** (random 0.4757 / pop 0.5715 exact / FM 0.5953) — environment trusted; if a future run's random self-check drifts from ~0.475, fix the harness before believing anything else.
8. **Test labels live on this disk but are off-limits during development.** Agent sees validation only; test is scored once at the end. Leak-guard: training rows must have date ≤ 20220421.
9. **Track 3's harness lessons carry over:** cheats to guard for (caching, timer games), noise floors before comparisons, journal written by the harness not by hand, champion = current harness version only.
10. **numpy champion-state saves must decouple:** restoring `best_state` without `.copy()` aliases the saved arrays to the live model — continued training then corrupts the champion in place (official it2/s001: returned a post-peak state, scored 0.6008 UNDER its own floor). Save by copy AND restore by copy.
11. **Within-user BPR fine-tune on the converged FM does not help** (official it3/s002: every fine-tune epoch scored below the warm start, 0.6006–0.6009 vs 0.6015, lr 5e-4, K=1). The pointwise FM is already pair-consistent within users; swapping the loss on the SAME representation moves nothing. Ranking-loss gains here must come with top-heaviness (listwise/nDCG-aware) or with NEW information (sequences), not from plain pair reweighting.
12a. **Explicit count-crosses of field pairs FM already embeds are redundant** (official it5/s004: LOO-smoothed user→author affinity field scored 0.601309 ≈ baseline to within noise). The u×a embedding dot product IS a learned affinity from the same rows; counting it again adds nothing. New information must come from OUTSIDE the (fields × long_view) span: unused feedback signals, temporal order, or attention-style capacity. Also: avoid the words signal/inspect in solution prose — they trip scanner flags meant for code.
14. **Combine proven mechanisms at the SCORE level, never by joint training** (it13: DIN+aux jointly trained scored BELOW either component — aux gradients inflated the attention gates; it14/it15: rank-average blending of separately-trained models added +0.0005 on top of the best single model). Also: rank-averaging ≥ standardized-mean averaging; a weak seed still helps its ensemble; keep the incumbent weighting in every candidate set so a polish can't regress.
13. **Label-side and sequence information are the live fronts** (it6: watch-ratio aux head +0.0003 at α=0.3, non-monotonic in α, aux head itself never ranks better — pure small regularizer; it9: DIN-lite causal attention over engaged history +0.0007, gate self-opened to +0.17). Static-feature and loss-family moves are dead; behavioral sequence capacity is the first mechanism the model itself chose to use.
12. **Listwise softmax fine-tune fails the same way** (official it4/s003: epochs sink monotonically 0.6000→0.5990, lr 2e-4). Combined with LESSON 11: the ENTIRE ranking-loss-swap family on the stock 5-field representation is a dead end — the representation, not the loss, is the bottleneck. Corollary: fine-tuning any new objective from the validation-selected pointwise peak goes immediately downhill and keeps sinking; don't buy more retunes (lr/patience) of this family. New information (behavioral crosses/sequences) is the only open front on the model side.
